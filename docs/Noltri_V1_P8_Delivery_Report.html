一 结论与「全部完成」判定

P8 的验收口径是开发文档的阶段表（「冷启动、离线、权限、异常、性能、安装升级与最终报告；实机演示、日志和测试对应；限制如实列明」）＋ §670 必交付产物表＋ §682 的「全部完成」四项判定。本轮把 P8 拆成五片：打包（随包运行时与四个单文件入口）、托管（安装版 App 自己拉起 Core 与 MCP）、M05（浏览器通道入口不再指向开发目录）、实机验收（冷启动／异常／恢复／重复提交）、回写与报告（README、FUNCTION_MAP、本报告）。

打包的结论一句话：安装版自包含。官方 Node v24.18.0（sha256 ee6fb0e0…）作为 sidecar 随包携带，Core／MCP／Native Host 三个入口由 esbuild 打成单文件 ESM 放进 Contents/Resources，App 启动时用包内运行时拉起它们、以探针确认就绪、退出时随带回收——全程不依赖用户机器上的 Node、pnpm、Rust 或任何云凭据。产物内 strings 扫描 0 处开发目录引用。

实机验收的结论一句话：从挂载的 dmg 直接运行通过了四个关键场景——冷启动（两侧车自拉起、数据目录生成）、采集闭环（原文／知识点／节点 1/1/1 落库）、异常退出（全部进程 SIGKILL、WAL 580 KB 未合并 → 重启重放后数据不变）、备份恢复（SQLite .backup 快照在新路径读回同一数据）＋ 100 次同键重复提交只落 1 行。证据（截图、健康 JSON、帧往返、MCP 握手）见 §五、§六。

十 失败与跳过项

过程中失败并已解决（如实记录）

  • dmg 首次打包失败：bundle_dmg.sh 首跑被 Finder 自动化的 TCC 提示挡住（首次控制 Finder 需用户确认），报错被 tauri 的管道吞掉只留 exit 1；手动重跑同一脚本即通过，随后用 --bundles dmg 正式重跑通过。
  • dmg 第二次打包失败：bundle/macos/ 里留下的旧 dmg 挡住 convert 步骤；清理残留后通过。两次都是环境／残留问题，产品构建本身无缺陷；教训已写进本节（构建前清 bundle 残留）。
  • --bundles dmg 会清掉 bundle/macos/ 的中间 .app（tauri 行为）——随后补跑 --bundles app 使两个产物同时存在（本报告 §四 的 .app 即来自这次重跑）。

本轮跳过（有原因，不伪装）

  • 浏览器 manifest 实写：扩展仍无 nativeMessaging 权限——替用户领新权限属「不得静默进行」的决定，保持预览态。
  • 辅助功能（AX）授权与捕获交互：未授权（截图如实显示），选区／胶囊／快捷键未点验。
  • 公证：本机 0 个 Developer ID，无法执行。
  • 真实模型调用：BYOK 网关调用未做（测试一律 offline）；安装版按设计不接第三方凭据。
  • 升级安装／端口占用演练／磁盘不足与只读目录／真实 Chrome 加载扩展／1 万条量级查询与 P95 性能：未做，逐条列明。
