# Notes 0.1.0

Status: first Notes release, packaged for manual installation. Publishable artifacts are the files attached to the official Release; an unlisted local build is not a public download.

## Install and data

- macOS target: Apple Silicon, macOS 13.5 or later.
- Desktop bundle identifier: `com.noltri.notes`.
- Default macOS profile: `~/Library/Application Support/com.noltri.notes/`.
- Core's source-run default profile: `~/.noltri-notes/data/`.

Install the DMG by moving `知序.app` to Applications. Back up data before replacing an existing installation: the bundle identifier and profile location are shared with prior Notes builds. The retired course product line is not migrated automatically.

If macOS blocks first launch, follow [Apple's safe-opening guidance](https://support.apple.com/en-us/102445). This ad-hoc signed build is not notarized; system prompts and permissions depend on the Mac and its security settings.

## Included workflows

- **Navigate knowledge:** Open **学科与方向** in the sidebar and choose a subject, direction or topic. The right panel's **学科图谱** shows local relationships; **本学科全部节点** expands the selected discipline. A chapter shared by multiple topics remains one chapter and opens by its stable identity from the graph.
- **Collect from the desktop:** In **全局快捷键**, set and save shortcuts for screenshot selection and opening the collection window. The selected-text overlay is optional and off by default; enable it separately, then grant macOS Accessibility access in **System Settings → Privacy & Security → Accessibility**. It observes selected text only in TextEdit and Notes and submits text only after you click **收集**. It does not monitor browser selection.
- **Collect from Chrome:** Load the unpacked extension in Chrome's Developer mode. In extension settings, set the local Core URL and access token, then save; Chrome asks for access to that API origin. The token is stored in Chrome Sync. Use the context menu or extension popup to collect. When Core is unreachable, retryable captures stay in the local extension queue; use **立即发送** after reconnecting. The queue expires after seven days and is disabled in Incognito.
- **Configure models:** In desktop **Provider 管理**, add a provider, set its API endpoint and key, save, then fetch or enter a model ID and select **使用此模型**. This saves the selection and applies it to the local managed service. For the tested `deepseek-flash` entry, open the model-options disclosure, enable **图片** (leave **文本** enabled), and save the provider before using image recognition. In the Inbox, select the image item and click **处理图片**. With image input disabled, the tested image stayed in `assets_saved/unsupported` and no OCR request was sent.

## Manual-only update model

Version 0.1.0 ships without a signed updater archive, `.sig` file or `latest.json`. Install updates manually from the official Release page. The updater endpoint and signature/version checks remain configured for future signed releases; missing release metadata currently produces a generic `update_check_failed` error. This failure is closed: no update is accepted or installed, and the error does not mean the app is up to date.

The local build disabled only Tauri updater artifact generation for this manual-install package. It used ad-hoc signing and did not read or use the updater signing key. Future updater releases must keep signature verification enabled, require signed versions and reject downgrades.

## Release build verification

The arm64 app and DMG were built on macOS 26.6.2 with Node 24.18.0, pnpm 11.21.0 and Rust 1.98.1. Rust source paths were remapped to a neutral `/rustc` prefix; a scan of the final app bundle found no build-host home paths. The official macOS verifier confirmed strict/deep code integrity for the app and the DMG-mounted copy, checked the bundled Node runtime's SQLite/JIT support, and verified the DMG image. An earlier executable built from the same first-party sources passed Graph navigation and search for Python, C++ and C shared-chapter contexts. The final path-remapped bundle also launched with an isolated synthetic profile and passed a C++ Graph shared-chapter check: the opened note path and body matched the C++ sentinel, while its isolated Core/MCP services returned HTTP 200. From the shared C++ chapter, Tab → Right → Enter opened the C overview. The About dialog displayed version 0.1.0 and the bundled icon; Dock appearance, existing-profile migration and arbitrary user content were not covered.

Automated checks on Node 24 passed: desktop and Core typechecks; Core 40 files/586 tests; MCP 4 files/24 tests; extension 10 files/141 tests; build-pipeline, NOTICE and detached-runtime contracts 16 tests; Rust AX selection 1 test; and Swift AX package 22 tests. Core and MCP used one worker without extending test timeouts. The broad desktop Vitest run passed 50 of 57 files (463 tests passed, 51 skipped); seven suites stopped in Chrome or component startup hooks before their product assertions. A serial Chrome-for-Testing retry was stopped after repeated startup-hook timeouts and produced no final aggregate. It did not establish that the desktop suite passes.

The extension ZIP passed manifest validation, and its Options page loaded and saved settings. A headful Chrome test also saved the configured synthetic Core URL and received the Core API-origin grant. A request for a second synthetic fixture origin timed out before queue capture. In a separate headless diagnostic, manual capture placed a text item in the extension's local outbox, but the Core inbox stayed empty; selection-to-Core delivery and retry remain unverified.

In a separate isolated synthetic sample using the earlier, pre-remap executable from the same first-party source inputs, enabling **图片** produced OCR text matching the three supplied lines; explicit confirmation then opened the archived text and direction read-only, and a DeepSeek explanation request succeeded. The metered proxy recorded one model-list GET and five successful chat POSTs, 2,500 input and 646 output tokens, an estimated cost of US$0.0015252, and no rejected requests. This is one synthetic sample, not a general OCR or model-quality claim. The model flow was not rerun on the final path-remapped executable.

This candidate uses ad-hoc signatures and is not Apple Developer ID signed or notarized. Gatekeeper assessment was disabled on the build host, so Gatekeeper acceptance was not evaluated. Earlier 3.0.0 collection, update and permission evidence applies only to those historical build identities.
