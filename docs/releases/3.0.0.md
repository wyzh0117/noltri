# Notes 3.0.0 — 当前源码目标

状态：3.0.0 的下载与更新工件以正式 Release 为准。此说明记录当前验证范围，不替代未完成的平台或模型验收。

## 产品线与数据身份

3.0.0 以当前 Markdown Notes 为维护主线。旧课程产品线不再维护，不提供课程工作区迁移或兼容承诺；历史 tag、发布工件和原有数据保留。

- 桌面 bundle identifier：`com.noltri.notes`。macOS 默认数据／配置位于 `~/Library/Application Support/com.noltri.notes/`。
- 从源码运行 Core 的默认 profile：`~/.noltri-notes/data/`，包含 `noltri.sqlite` 和默认 `vault/`。
- 默认 Core/MCP 端口为 `18887` / `18890`；外部连接默认关闭，需显式 opt-in、同值本机令牌和服务验证。
- Core/MCP 不再向上查找项目 `.env`。`NOLTRI_ENV_FILE` 是独占选择（缺失也不回退）；否则仅探测新 home 和显式 data 目录。
- 后续 3.x 使用同一命名空间。`NOLTRI_DATA_DIR`、`NOLTRI_SQLITE_FILE`、`NOLTRI_NOTES_DIR`、`NOLTRI_SETTINGS_DIR` 等显式覆盖继续有效。
- 不自动导入旧数据库。不兼容或无法识别的库继续在修改前拒绝，原文件保持不动。外部服务连接仍需确认其 profile 与版本。

## 当前功能范围

当前源码包含本地 Markdown 编辑／阅读、标题思维导图、搜索、属性、历史及关系图谱；关系和解读入口保留原文焦点，翻译、解释、提问为显式请求的临时派生结果。

文字、图片和截图收集保留原件，图片识别与整理结果分离。主窗口待确认资料支持人工判断；处理规则与记录位于独立窗口，规则草稿、应用和回退有明确边界。Agent/MCP 沿用授权范围。模型能力、真实识别与答案质量依赖实际 provider，不由合成测试保证。

桌面快捷键可明确配置，注册冲突或保存失败时保留旧组合；默认仍为 Control–Option–Command–S / V。同一配置目录的实例在注册快捷键和启动服务前持有系统文件锁。调试窗可按需读取本应用及其自有 Core/MCP 的有限进程元数据；确认旧进程退出前不启动下一代。独立 profile 可以并存，仍需分别选择不冲突的快捷键。源码回归和隔离实机记录按各自构建身份保留，旧冻结包的系统授权不替代当前候选的证明。此前6c验收构建已完成下述原件采集范围；此前审核入口修复构建已在合成资料上验证建方向、单次人工确认及实际知识稿持久化；其重开审核页显示错误已修复。当前发行候选已在原生界面和完整宿主／服务重启后验证原文、确认时人工稿及方向正确回填，唯一确认操作和业务内容保持。

## 此前6c构建的原件采集验收

此处6c指执行文件SHA256以6c9e5ab3开头的已验收构建；审核入口修复的新构建不继承其系统权限通过结论。

在隔离的合成资料 profile 中，com.noltri.notes / 3.0.0 的6c构建经用户实体收集热键导入40字符原文，再经实体截图热键和框选加入一张原图。图文仅正常提交一次，保存为同一批次的两条独立原件；正常退出并沿用同一配置重开后，原文、实际图片预览、PNG字节和原件顺序保持。

未配置模型时，文字整理明确失败，图片识别为 unsupported；本次证明的是原件保留与回读，不是 AI 整理或 OCR 通过。混合剪贴板中图片字节读取异常时保留可读文字的修复有单独合成回归，不声称覆盖所有真实剪贴板格式。首次现场空白的原因仍未确定。


## 审核前的原件详情入口

待确认资料在确认归档前即可打开“查看原件资料”，使用正常详情中的手动分类建立方向。正在处理或结果未确认的审核/图片工作会阻止进入可编辑详情；关闭详情后刷新原文状态，并保留归档草稿。此入口已在前一构建的原生界面验收通过；同轮发现重开后的确认稿与方向未回填，当前修复从精确来源及修订的持久化人工确认记录只读恢复，并在记录缺失时明确提示。读取不会重新确认或替换原文，本地未提交修改与确认时结果分开保留并可显式放弃。当前修复已有组件、存储与 Core 回归，并已用合成确认现场完成原生审核页和完整重开回填复验；没有重复确认、保存分类或调用模型。前述实体V/S与原件重开记录按原验收构建身份保留，不替代新构建的系统权限证明。
