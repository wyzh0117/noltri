## 缺陷与契约

分类 UI 没有暴露节点类型选项。根因是旧 writer 会把非叶级分类写成 `domain`，而 Graph 按 `discipline`／`subdiscipline` 类型查找范围节点。

修复新增共享 `node-taxonomy.ts`：手工分类和 AI 分类 writer 对多级路径写入 `discipline` → `subdiscipline` → 更深层 `domain` → 叶级 `topic`；单级路径继续写为根级 `topic`。Tree 和 Graph 读取时把旧的根级／分支级 `domain` 映射为 `discipline`／`subdiscipline`，保留旧节点的存储 ID 与原始类型。HTTP／SQLite 回归覆盖旧 domain 兼容、Graph scope 与原授权检查。升级旧用户库的真实 Graph／About 界面验证通过；原节点 ID 与存储类型未迁移。

- 摘录一致性为 48/49 字节精确匹配、49/49 内容核验通过。唯一例外是提取练习主题中一条摘录靠近末尾的 ASCII 双引号（U+0022）变为右弯双引号（U+201D）；其余字符完全一致，原始 raw 文本未修改。它像智能引号转换，但没有证据确认触发点，因此仅按单字符排版等价接受；该记录的 `exactSHA` 为 false。后续录入采用原生粘贴，以降低智能标点转换风险。
- 首次 QuickCollect 的 HTTP 401 是采集过程中的历史事件：当次仅生成失败 raw，没有 item。之后用应用已有的“保存分类”流程恢复同一 raw 并成功入库，没有重复提交或重复 item。原生 Provider 配置读取链路一致，401 本身不能判定凭据过期、撤销、权限不足或其他账户原因。恢复时读取已有备用 provider 模型列表成功，随后按用户授权启用已保存的 `glm-5.3`；没有新增账户、密钥或订阅。升级时 settings/grants 保持原样，采集恢复阶段仅改变了既有 active provider/model 选择。

### 来源筛选、勘误与非程序性恢复

- OpenStax 候选页面的许可条款限制未经许可的 LLM 训练或生成式 AI 摄入，因此本轮未使用该来源。此限制也列在 [OpenStax 官方章节许可说明示例](https://openstax.org/books/introductory-statistics-2e/pages/1-key-terms)中。
- [Global warming](https://en.wikipedia.org/wiki/Global_warming) 重定向到 [Climate change](https://en.wikipedia.org/wiki/Climate_change)，会与已有主题来源重复；因此替换为内容不同的 [Climate change mitigation](https://en.wikipedia.org/wiki/Climate_change_mitigation)。提取练习主题中，原候选落到错误页面后换成 [Testing effect](https://en.wikipedia.org/wiki/Testing_effect) 和 [Spaced repetition](https://en.wikipedia.org/wiki/Spaced_repetition)。
- 气候论文主文 DOI 为 `10.1371/journal.pclm.0000303`；另列 2024-08-29 更正 DOI `10.1371/journal.pclm.0000487`。更正说明 Fig. 2 重复 Fig. 1，并提供正确的 Fig. 2。主文按 PLOS 页面标注为 CC0；更正页只作为勘误来源链接，不作为主文摘录来源。
- 预检时 PLOS 页面曾遇到 tracker 加载超时，但现有 DOM 内容仍可读取；这是浏览器非程序性加载问题，不据此认定来源内容无效。Ego Lite 出现 0.5.1.13 更新提示时按用户指示未升级，继续当前采集流程。
- “贝叶斯定理”第一次 QuickCollect 收到服务方 HTTP 401，只生成 raw failed，没有 item。原生 Provider 设置读取链路核对一致；单凭 401 无法判断凭据过期、撤销、权限或其他账户原因。之后通过应用已有“保存分类”流程恢复同一 raw 并成功保存，没有重复 QuickCollect 或重复 item。已配置的备用 provider 可读取模型列表；用户允许后，操作员切换到已保存的 `glm-5.3` 模型并继续采集，没有新增 key、账户或订阅。升级时 settings/grants 保持不变；此后采集恢复只改动既有 active provider/model 选择。
- 一次只读来源审计初稿因把英文勘误说明与中文引导语逐字比较而误报。复核主文和更正页的 DOI、URL、日期及 Fig. 2 重复 Fig. 1 并提供正确图的事实后，调整为核验这些实质字段；来源信息完整，未改产品、来源原文或用户数据库。一次计划用于采集 Graph 的截图误捕获了前台浏览器窗口，复核时识别并删除，未 stage 或上传；没有把它作为产品证据，最终使用已核实的原生 UI／AX 状态和数据库终验。临时审计脚本修正后通过运行检查，不涉及产品代码。
