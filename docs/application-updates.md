# 应用内更新

本文描述 Notes 的签名更新实现。0.1.0 首发为手动安装版本，没有签名 updater 归档、签名文件或 `latest.json`，因此本版没有可用的应用内更新源。请从正式 Release 手动下载 DMG；缺少 `latest.json` 时应用会安全返回通用检查失败，不会把它报告为“已是最新”。

桌面使用稳定的 `com.noltri.notes` profile，源码 Core 默认使用 `~/.noltri-notes/data`。旧课程线不再维护，不提供自动迁移；历史工件和原数据保留。手动替换已有安装前备份数据并核对 profile 归属；显式路径覆盖和外部服务连接也需核对，未知或不兼容数据库仍应在修改前拒绝。

当前开发实现使用官方 Tauri updater 组件和项目专用更新公钥验证发行工件。更新签名与 Apple Developer ID 签名、公证是不同机制；更新包验签通过不表示已经完成 Apple 公证或屏幕录制授权。

## 使用流程

1. 在桌面应用的 Provider 管理窗口中点击“检查更新”。启动应用不会自动检查或下载。
2. 发现新版本后，点击“下载并验证”。验证完成后仍未安装。
3. 保存笔记、审核与 Provider 草稿，完成收集和处理任务，并保存关闭规则调试窗。
4. 点击“确认安装并替换应用”；安装完成后再明确点击“确认重启应用”。部分平台的安装流程本身可能退出应用。

本机或服务活动状态不明时会阻止安装或重启。安装结果不明时不自动重试或重启，先保留当前数据并人工核对应用状态。隔离的同ID测试包已完成下载验签、安装、正常重启与原图预览；无效归档的安装失败后数据保持，并完成一次人工备份恢复。自动回滚、旧版首次失败原因及具体失败边界尚未证明。正式发行工件以 Release 中的签名、版本与哈希为准；上述更新实机结果仅对应隔离测试包，未测能力按版本说明保留限制。

## 发行维护

客户端固定 HTTPS 更新端点及公钥，要求签名版本，不允许降级或跳过证书验证。版本元数据使用官方 updater 格式；`latest.json` 与对应平台工件、签名共同发布。单独发布 SHA256 无法代替签名真实性。

发布顺序：先确认版本、Notes profile 与数据库安全检查，再运行构建及测试，生成平台 updater 工件，以项目专用私钥在受控本机签名，验证签名与版本，最后一并发布工件及 `latest.json`。私钥与口令不得进入源码、构建日志、Git、Release 或文档；加密私钥需要本机隐藏输入。修改信任公钥需要独立的密钥轮换方案，不能直接让已安装客户端信任任意新密钥。

历史工件及其系统身份应保留。新 Notes 身份不继承旧应用的系统权限；ad-hoc 重建也可能改变代码身份。更新包签名不固定 macOS 屏幕录制权限身份，也不自动授予权限。

官方参考：[updater 组件](https://v2.tauri.app/plugin/updater/)、[应用发布与更新](https://v2.tauri.app/distribute/)。

Noltri Notes 默认 Core/MCP 端口为 `18887` / `18890`，避免自动接到旧线默认服务。外部运行时需要 `NOLTRI_USE_EXTERNAL_RUNTIME=1` 以及与 Core/MCP 一致的显式本机令牌；更新前仍按当前连接服务核对活动状态。
