# 收集、审核与阅读模块

本文说明当前工作区源码中的模块行为。已发布版本的功能、工件和下载以对应 Release 与发行记录为准。

| 模块 | 使用方式 | 数据边界 |
| --- | --- | --- |
| 快速收集 | 输入文字、添加图片，可拖动图片或用“上移/下移”调整顺序。每张图片可标注或顺时针旋转 90°。可选择纵向或横向拼接，并按队列顺序生成预览 | 标注与旋转按原图生成派生图，拼接预览按队列顺序生成派生图。提交时派生图与原图分开保存并保留来源顺序。提交前队列保存在当前窗口中，请确认保存成功再关闭 |
| 截图 | 使用桌面快捷键完成系统选区，再在收集窗检查 | 原图与来源分别保存；取消选区不会提交新图 |
| 待确认资料 | 在主窗口确认分类与整理文本，或暂缓、拒绝、恢复 | 处理状态与人工审核状态独立；编辑整理文本不改原文 |
| 图片识别 | 在图片资料中查看原图、附文与独立识别结果，明确触发处理 | 识别不支持或离线时保留原件；歧义输入不会自动猜选 |
| Markdown 笔记 | 在同一正文中编辑、阅读、查看标题思维导图 | 思维导图只读，正文仍由笔记编辑器保存 |
| 知识导航与 Markdown | 从学科与方向、搜索和范围卡片打开主题、章节或 Markdown 文件 | 主题与章节按 Core 稳定 ID 和路径映射定位；独立 Markdown 按 Vault 路径定位，同名也保持独立。正文/阅读视图隐藏 YAML；源码视图保留原始 frontmatter。自定义属性与正文经同一带 etag 的保存路由写入；系统身份字段不可编辑，冲突或失败时保留草稿 |
| 关系与解读 | 关系页查看图谱、属性与链接，可切换“学科图谱”或“高级网络”。学科图谱提供“当前对象局部图”，在一级学科卡片页可选“本学科全部节点”。高级网络提供“当前对象”“本学科”“全部资料”范围，并可分别筛选标签、附件、待建引用。跨学科查看需主动选择“全部资料”。解读页需明确请求翻译、解释或提问 | 解读使用提交时的正文快照，临时显示，不覆盖笔记 |
| 规则与处理记录 | 从主窗口打开独立调试窗，编辑草稿、应用或回退版本 | 保存草稿不会生效；已启动任务保留其冻结规则，回退产生新版本 |
| Agent / MCP | 通过应用提供的本机 MCP 入口读取知识或提交收集内容 | 继续使用现有鉴权与授权范围；规则管理不是 MCP 写入口 |

关系侧栏缩小状态下，Graph 位于正文辅助工具上方。点击“展开”可放大 Graph 并隐藏正文工具，点击“收起”可恢复缩小布局。缩小状态下可拖动两者之间的分隔线调整 Graph 高度。正文工具顺序为“大纲、反向链接、出链、标签、来源与属性”。焦点位于工具标签时，可用左右方向键切换。

图片识别需要用户在桌面 Provider 管理中，为所选 OpenAI Chat Completions 模型明确勾选“图片”输入能力并选中该模型；托管启动或应用模型配置时，将其 ID 通过 `AI_IMAGE_RECOGNITION_MODEL` 传给 Core。取消图片能力、切换到文本模型、停用模型或选择当前未实现图像适配的 Responses/Anthropic 协议时，会显式清除此配置。识别仍需用户点击“处理图片”，选择模型或保存原件不会自动发起图像请求。独立 Core 部署可显式设置同名环境变量。离线保存成功不代表已完成 OCR 或知识分类；合成回归不代表真实提供方的识别质量。

文字与图像的原件、派生识别内容、整理条目分别保留。处理失败可以重试；重复请求复用既有来源与处理计划。人工确认后重新分析受保护，避免覆盖已审核内容。

规则调试窗只显示处理元数据，不显示原文、模型密钥或文件路径。关闭调试窗不停止知识库服务。更新前需要保存并关闭该窗口。

桌面设置可分别配置截图与打开收集窗的全局快捷键：使用 A–Z 和至少两个修饰键，默认仍为 Control–Option–Command–S / V。保存时检查组合冲突；无法注册或保存时保留原配置。配置只作用于本应用，不更改系统或其他应用快捷键。界面显示当前生效的组合；单击截图入口仍可使用。未保存的快捷键草稿也会阻止安装更新。

选中文字浮层默认关闭；启用后只观察当前前台的 TextEdit 与备忘录，选区稳定后显示按钮，必须单击“收集”才会提交。浏览器选区交接仍待浏览器侧握手；Control–Option–Command–V 剪贴板收集与 Control–Option–Command–S 截图是独立入口，不依赖该浮层。

同一桌面配置目录只允许一个宿主启动快捷键和托管服务。显式指定不同配置目录时允许独立实例；它们仍可能竞争相同全局快捷键，需要分别配置。锁文件由系统持锁，不通过删除文件或猜测 PID 判定旧实例。处理调试窗可明确刷新本应用与自有 Core/MCP 的进程元数据；外部服务不归本应用终止，终止请求成功也不等于已确认退出。

Notes 3.x 是当前维护主线，使用独立的 `com.noltri.notes` 桌面 profile 和 `~/.noltri-notes/data` 源码运行默认目录。旧课程产品线不再维护，不提供自动导入或兼容承诺；历史版本、工件和原有数据保留。不兼容数据库仍在修改前拒绝，显式 profile 覆盖仍需核对数据归属。

默认 Core/MCP 端口为 `18887` / `18890`。源码启动需显式选择 `NOLTRI_ENV_FILE`，不向上查找项目 `.env`；显式文件缺失也不回退其他配置。桌面外部连接默认关闭，需明确 opt-in、同值本机令牌和服务验证。


桌面托管启动会为当前新 profile 创建受限本机设备凭据，并由同一会话启动 Core/MCP；主窗口与规则窗复用已认证连接。端口被其他服务占用时会停止启动，请先核对服务归属。连接外部运行时会验证 Core 认证和 MCP initialize，但仍需自行确认二者使用同一 profile 与合适版本。

Agent 客户端需要带认证信息的连接配置。主窗口的“复制 MCP 连接配置（含本机凭据）”仅在明确点击后写入剪贴板；只复制 URL 不会包含认证。请仅粘贴到本机受信客户端的配置中。

受片段长度限制的客户端，原文、来源上下文、失败文本和手工归档响应按授权上限投影；未限制客户端继续读取完整内容。投影不改写已保存原件或知识项全文。
